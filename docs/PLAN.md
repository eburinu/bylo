# План на день — нас трое

Время — по расписанию хакатона. Если стартуем позже, сдвигаем контрольные точки
и режем с конца (см. «Что резать»).

## Роли

### Иван (Claude) — «движок» · `engine/`
1. Клиент LLM + генератор соседей: персоны × модели × тон (`data/personas.json`,
   `prompts/generator.txt`), 10–15 запросов параллельно, ретраи, строгий JSON.
   Сначала 20 соседей, потом 100.
2. Нормализация каждой идеи в `mechanic` (`prompts/normalize.txt`).
3. Эмбеддинги (`intfloat/multilingual-e5-small`, запасной вариант — API),
   кластеры, подписи кластеров через LLM, 2D-проекция.
4. `engine/api.py`: `/api/map` и `/api/check` по `docs/SCHEMA.md`, кэш.
5. После обеда: поворот + перепроверка (`prompts/twist.txt`).

### Участник 2 (Claude) — «витрина и валидация» · `web/`, `validation/`
1. Страница на моках из seed: карта (Plotly), поле ввода, карточка вердикта,
   состояние «считаю…».
2. Парсер Devpost: название + tagline проектов выбранных хакатонов →
   `data/validation/<id>.json`.
3. Метрика покрытия: доля реальных проектов, у которых есть «сосед» выше порога.
   Контроль: соседи по *чужому* брифу должны покрывать заметно меньше.
4. После обеда: подключение к API, полировка, проверка на ширине телефона.

### Участник 3 (без Claude) — «данные, судья, сцена» · `data/briefs/`, `data/validation/`, `data/gold/`, `pitch/`
1. **Сразу:** разметить `data/gold/pairs_to_label.csv` — 60 пар, колонка `same`:
   да / частично / нет («это одна и та же идея по механике?»). Сохранить как
   `data/gold/pairs.csv`. Это калибровка порога — без неё цифры не защитить.
   Открывать удобнее в Google Таблицах.
2. Найти на Devpost 2 тематических хакатона с ≥40 проектами, текст задания
   положить в `data/briefs/<id>.md`. Если парсер не взлетит — выписать
   40 названий + описаний вручную в `data/validation/<id>.json`.
3. Когда появится карта — проверить подписи кластеров на адекватность.
4. Слайды, сценарий демо, вопросы жюри с ответами; следить за временем команды;
   запасное видео демо в 16:30.
5. На защитах (по желанию) — по строке на каждый показанный проект.
   Показываем только суммарно, без названий команд.

Коммитить можно через веб-интерфейс GitHub (Add file → Upload files).

## Питч (2 минуты)
1. Крючок: «Утром мы придумали идею, потом спросили ИИ-соседей то же, что спросили
   вы, — и нашли её у них. У одного совпало даже название».
2. Проблема: ИИ делает каждого креативнее, а всех вместе — одинаковее
   (Doshi & Hauser, Science Advances 2024).
3. Демо: карта сегодняшних тем → наша первая идея в плотном кластере → член жюри
   называет свою идею → вердикт и поворот.
4. Цифра: валидация на Devpost с контролем.
5. Слайд конвейера (критерий «ИИ»): генерация разными моделями → нормализация →
   эмбеддинги → порог по человеческой разметке → поворот с перепроверкой.

## Неудобные вопросы — отрепетировать
- «Соседи — одна модель»: разные семейства моделей + проверка на реальных людях (Devpost).
- «Кому это нужно, кроме хакатонщиков?»: одна конкретная история — гранты или названия продуктов.
- «Чем лучше поиска конкурентов?»: поиск показывает, что уже сделано; «Было» — что сделают одновременно с вами.
- «Это наезд на соседей?»: нет, это симптом общего инструмента, а не упрёк.
